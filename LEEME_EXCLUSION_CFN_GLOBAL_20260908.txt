CLEAR - EXCLUSIÓN GLOBAL DE CFN
Fecha: 08/09/2026

OBJETIVO CORREGIDO
CFN deja de mostrarse como estado técnico en CLEAR, pero sus filas se conservan
porque contienen las activaciones que ALM_VALUE clasifica como FALLA o ALARMA.

INSTALACIÓN
1. Copiar las carpetas incluidas en este parche sobre la carpeta actual de
   CLEAR, conservando la estructura. El paquete contiene únicamente archivos
   nuevos o modificados.
2. Abrir SQL Server Management Studio y conectarse con una cuenta que pueda
   crear o modificar vistas y procedimientos en LC_MDB.
3. Fuera del horario de mayor uso, ejecutar una sola vez:
   SQL\CLEAR_RESTAURAR_FALLAS_OCULTAR_CFN_20260908.sql
4. Comprobar que los controles finales RESULTADO indiquen 0.
5. Actualizar el navegador con Ctrl+F5. No es necesario reiniciar IIS.

SI YA SE EJECUTÓ LA PRIMERA VERSIÓN
Ejecutar únicamente SQL\CLEAR_RESTAURAR_FALLAS_OCULTAR_CFN_20260908.sql para
restaurar las Fallas y reconstruir las cachés.

VERIFICACIÓN POSTERIOR
Se puede ejecutar en cualquier momento, porque es de solo lectura:
SQL\CLEAR_VERIFICAR_EXCLUSION_CFN_20260908.sql

ACLARACIONES
- No se debe cambiar la configuración de Alarm ODBC.
- dbo.FIXALARMS no se borra ni se modifica: continúa siendo propiedad del SCADA.
- La aplicación redirige sus lecturas a vistas CLEAR que ocultan el texto CFN
  sin eliminar el registro de alarma.
- El script reconstruye las cachés para recuperar las activaciones en Falla.
- La reconstrucción semanal toma 120 días, suficiente para las 16 semanas
  disponibles en las pantallas actuales.
