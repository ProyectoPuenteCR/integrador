# Ficha de monitoreo de pozos PCP

## Alcance

La grilla `telemetria_pcp.php` abre una ficha de pozo al hacer clic sobre una fila o presionar Enter. La ficha usa el formato de Monitoreo de Pozos y se abre maximizada.

Incluye identificación del pozo, batería, comunicación, estado PCP, comentario, última alarma, contador de alarmas de 24 horas, indicadores de producción e históricos PI. El estado proviene de `YT:POZO` y la presión de fondo de `PT:FONDO`. Las cartas dinamométricas no se muestran para PCP. La zona de tendencias ocupa todo el ancho disponible.

Los botones, enlaces y casillas existentes de cada fila mantienen su acción. La actualización automática de la grilla espera mientras la ficha está abierta. Se conservan el acceso a PI Vision, los permisos existentes y la selección de columnas de la grilla. La ficha permite ver también los datos de las columnas ocultas.

## Históricos

Se consulta el catálogo existente `LC_MDB.dbo.PI_Points_Stage`. Para PCP se verifican las familias exactas `<pozo>(PC12)_`, `<pozo>(PC14)_`, `<pozo>(PCP)_` y `<pozo>_`, con el atributo exacto y el sufijo `.PV` cuando corresponde. Una variable sólo se habilita si existe una correspondencia única con un WebId válido. Las correspondencias ambiguas o ausentes se indican en pantalla.

Estos candidatos requieren comprobación con los nombres reales de producción. Los valores actuales de la ficha se obtienen de la grilla aunque el histórico no tenga correspondencia. Las columnas de producción muestran los datos actuales disponibles; no se fabrica un histórico PI para los valores de Zafiro.

El usuario puede seleccionar variables, fechas Desde/Hasta y frecuencia de muestreo. Se conservan los valores cero y los estados digitales; las muestras de mala calidad aparecen como huecos. Hay exportación Excel y agregado al reporte cuando el usuario tiene acceso. Las fechas se interpretan en horario de Argentina.

Límites: hasta 12 variables, 31 días, 10.000 muestras por variable y 60.000 muestras por consulta. Los históricos usan una petición agrupada a PI Web API. Se reutilizan el transporte PI compartido y su configuración existentes en la rama de trabajo; esta actualización no cambia ese transporte ni la configuración de conexión.

## Alarmas y comentarios

El contador de alarmas usa `TELEMETRIA_POZOS_GENERAL_CACHE`, igual que la grilla. La ficha no vuelve a contar filas de `FIXALARMS`. La última alarma se busca con `TOP (1)` y coincidencia exacta del pozo. Si falta el contador en caché se muestra `—`; no se lo interpreta como cero.

Los enlaces de la ficha y de la grilla PCP envían `pozo_exacto=1`. La pantalla de alarmas y su exportación conservan ese filtro para evitar incluir pozos con nombres parecidos. La búsqueda general por texto mantiene su funcionamiento habitual cuando el parámetro exacto no está presente.

Se utilizan el sistema y los permisos de comentarios existentes. El formulario exige comentario y nombre del autor. Un usuario con permiso de escritura, sin lectura, puede agregar su comentario sin solicitar el contenido anterior. La ficha no modifica el esquema SQL ni la carga de SCADA.

## Archivos de integración

El archivo común `includes/telemetry_grid.php` conserva la habilitación de la ficha para `monitoreo_pozos` y `telemetria_pcp` de la entrega anterior. Las API validan explícitamente esos dos orígenes. Las demás grillas conservan su funcionamiento.

Esta actualización no modifica `assets/js/telemetry_modal.js`, `app.css`, Chart.js, archivos de configuración, credenciales ni archivos SQL. Los cambios de 3Sigma presentes en `main` quedan fuera del delta de esta actualización.

El parche permite detectar esas diferencias antes de aplicarlo.

Desde la raíz de una copia del repositorio se puede verificar el parche con:

```sh
git apply --check CLEAR_Ficha_PCP_20261030.patch
```

Si la comprobación informa diferencias, integrar los cambios con la versión instalada antes de copiar archivos a IIS. El paquete contiene sólo el delta del 30/10 sobre la entrega previa de la PR #2 y una vista previa con datos de ejemplo. Para una instalación que todavía no tiene esa entrega, usar el conjunto de cambios de la PR #2. La vista previa no consulta PI ni SQL Server.

## Validación

Se aprobaron 12 pruebas de interfaz en Chromium, 4 pruebas funcionales de backend con datos simulados y la comprobación de sintaxis de 10 archivos PHP en PHP 7.4.33. Las pruebas de ficha cubren escritorio y móvil, apertura/cierre, teclado, valores cero, columnas ocultas, acciones existentes y ausencia de cartas BM en PCP. Las pruebas de históricos cubren selección PCP, calidad de datos, exportación, permisos, fechas y límites. Las de actividad cubren contador desde caché, coincidencia exacta, datos ausentes y permisos de comentarios.

La prueba original del transporte PI no pudo ejecutarse en el runtime WebAssembly: necesita declarar funciones simuladas de cURL y ese runtime ya las incorpora estáticamente. Sus aserciones no se ejecutaron. El transporte se conserva sin cambios respecto de la rama existente.

La validación con datos reales de IIS, SQL Server y PI requiere acceso al entorno de CLEAR. Esta entrega no acredita una instalación ni una prueba en producción.
